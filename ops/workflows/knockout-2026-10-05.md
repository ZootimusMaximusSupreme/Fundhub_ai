## K3 proposal (step 1 done 2026-10-05, waiting on Chris)

**How "showed" works today.** DPC-02 (`src/workflows/dpc-02-call-outcome-enforcement.mjs`, lines 30-33) calls a client "showed" if any `call.completed` event exists. That includes a closer's "No show" log and every AI-setter (robot) call. The BS-01 pre-call emails use the same test (`callHappened`). Nothing records that a calendar booking was actually held: `completed` is in the word list but no code writes it.

**Proposed rule.** A client showed for a booked call when a closer logged Deposit, Downsell, Callback or Not a fit for them at or after that call's booked start time. Demo rows never count. Nothing else counts. The rule lives in `src/sales/call-outcomes.mjs`. DPC-02's `callHappened` uses it, and BS-01 follows because it imports `callHappened`. No database change.

| Case | Showed? |
|---|---|
| Closer logged Deposit, Downsell, Callback or Not a fit | Yes |
| Closer logged No show | No |
| AI-setter (robot) call, any result | No (it is a confirm call) |
| Calendar time passed, no closer log | No |
| Rescheduled or cancelled | No (only the new time can count) |

**ShowedCall.** Sent from the server, once per closer log that passes the rule, the same way Purchase is: a new `src/handlers/meta-showed-call.mjs`, through `src/messaging/providers/meta-capi.mjs`, behind `META_CAPI_ENABLED`, id `showed.<closer log id>`, skipping demo clients.

**Questions for Chris (recommendation first):**
1. Does "Not a fit" count as showed? Recommend yes: they came, and a no would send them no-show texts.
2. Should DPC-02 stop when a call is cancelled, and check again at the new time when it is moved? Recommend yes. Without this, once the rule is fixed, people who cancel or move would get no-show texts.
3. Should a late closer log (after the 5-minute check) stop the no-show texts and move the card to showed? Recommend yes.
4. Journey gap (CLAUDE.md §4): no intended journey has a "did they show" step or a Meta event. Build with just the flow page and report the gap, or does Chris add the step to the client journey first? Recommend build now and report the gap.
